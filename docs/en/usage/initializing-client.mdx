## Basic Setup

To start using NotCMS, you need to initialize a client with your schema and credentials:

{/* docs-check */}
```typescript
import { Client } from 'notcms';
import { schema } from './notcms/schema';

const nc = new Client({
  schema,
  secretKey: process.env.NOTCMS_SECRET_KEY,
  workspaceId: process.env.NOTCMS_WORKSPACE_ID
});
```

## Prerequisites

Before initializing the client, ensure you have:

1. **Generated schema** - Run `npx notcms init` to generate the first schema, then `npx notcms pull` to update it
2. **Environment variables** - Set up your API credentials
3. **Installed NotCMS** - Add `notcms` to your project dependencies

## Environment Variables

### Required Variables

```env
NOTCMS_SECRET_KEY=your-secret-key
NOTCMS_WORKSPACE_ID=your-workspace-id
```

### Loading Environment Variables

<Tabs>
  <Tab title="Next.js">
    ```typescript
    // Next.js loads .env.local automatically
    import { Client } from 'notcms';
    ```
  </Tab>
  
  <Tab title="Node.js">
    Node.js can load the file itself:

    ```bash
    node --env-file=.env.local app.ts
    ```

    With `dotenv`, load the generated client after `dotenv.config()` with a
    dynamic `import()`. A static `import` runs first, before the variables are
    set.

    ```typescript
    import dotenv from 'dotenv';
    dotenv.config({ path: ".env.local" });
    
    const { nc } = await import('./notcms/schema');
    ```
  </Tab>
  
  <Tab title="Vite">
    Keep the NotCMS client in a server endpoint or server-side rendering path.
    Do not put `NOTCMS_SECRET_KEY` in a `VITE_` variable: Vite exposes `VITE_`
    values to browser code. Load the secret in your server runtime and pass it
    to `Client` there.

    The generated `notcms/schema` module also creates a client from
    `process.env` when it is imported, but Vite does not copy `.env` files into
    `process.env`. Copy the `NOTCMS_` values there in your Vite config (for
    Astro, `astro.config.mjs`), as the
    [Astro example](https://github.com/qqpann/notcms/tree/main/examples/astro)
    does:

    ```typescript
    // vite.config.ts
    import { defineConfig, loadEnv } from 'vite';

    export default defineConfig(({ mode }) => {
      // Values from the deployment environment take precedence.
      const local = loadEnv(mode, process.cwd(), 'NOTCMS_');
      for (const [key, value] of Object.entries(local)) {
        process.env[key] ??= value;
      }
      return {
        // your existing config
      };
    });
    ```
  </Tab>

  <Tab title="Cloudflare Workers">
    Workers put a Worker's variables and secrets in `process.env` when the
    `nodejs_compat` compatibility flag is on and the compatibility date is
    2025-04-01 or later. Compatibility dates from 2026-08-04 turn the flag on
    by default.

    ```jsonc
    // wrangler.jsonc
    {
      "compatibility_date": "2026-11-01",
      "compatibility_flags": ["nodejs_compat"]
    }
    ```

    Without it, `process.env` is empty, and importing the generated
    `notcms/schema` module fails with `secretKey is required`, even when you
    pass the values to `Client` yourself. Store the key with
    `npx wrangler secret put NOTCMS_SECRET_KEY`, and set `NOTCMS_WORKSPACE_ID`
    in `vars` or as a secret.
  </Tab>
</Tabs>

## Framework-Specific Setup

### Next.js App Router

```typescript
// app/lib/notcms.ts
import { Client } from 'notcms';
import { schema } from '@/notcms/schema';

// Server-only client
export const nc = new Client({
  schema,
  secretKey: process.env.NOTCMS_SECRET_KEY!,
  workspaceId: process.env.NOTCMS_WORKSPACE_ID!
});
```

### Remix

```typescript
// app/lib/notcms.server.ts
import { Client } from 'notcms';
import { schema } from '~/notcms/schema';

// Mark as server-only with .server.ts extension
export const nc = new Client({
  schema,
  secretKey: process.env.NOTCMS_SECRET_KEY!,
  workspaceId: process.env.NOTCMS_WORKSPACE_ID!
});
```

### SvelteKit

```typescript
// src/lib/notcms.ts
import { Client } from 'notcms';
import { schema } from '../notcms/schema';
import { 
  NOTCMS_SECRET_KEY, 
  NOTCMS_WORKSPACE_ID 
} from '$env/static/private';

export const nc = new Client({
  schema,
  secretKey: NOTCMS_SECRET_KEY,
  workspaceId: NOTCMS_WORKSPACE_ID
});
```

The generated schema module still reads `process.env` when it is imported, so
copy the values there as shown in the Vite tab above.

## Troubleshooting

### Common Issues

<AccordionGroup>
  <Accordion title="Environment variables not loading">
    - Check `.env.local` file exists in project root
    - Ensure your runtime loads `.env.local` (for example `node --env-file=.env.local`, or `dotenv` before a dynamic `import()` of the generated client)
    - The generated `notcms/schema` module reads the variables when it is imported. Passing `secretKey` and `workspaceId` to your own `Client` does not skip that read, so set them in the environment first (see the Vite and Cloudflare Workers tabs above)
    - Verify variable names match exactly
  </Accordion>
  
  <Accordion title="Authentication failed">
    - Verify `NOTCMS_SECRET_KEY` is correct
    - Check `NOTCMS_WORKSPACE_ID` matches your workspace
    - Ensure API key has necessary permissions
  </Accordion>
  
  <Accordion title="Schema not found">
    - Run `npx notcms pull` to generate schema
    - Check import path is correct
    - Ensure schema file exports correctly
  </Accordion>
  
  <Accordion title="TypeScript errors">
    - Update to latest NotCMS version
    - Regenerate schema with `npx notcms pull`
    - Check TypeScript version compatibility
  </Accordion>
</AccordionGroup>
