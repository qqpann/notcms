## Overview

The `pull` command generates or updates the configured TypeScript schema from
the databases registered in your NotCMS workspace.

```bash
npx notcms pull
```

`init` already performs the first pull. Run this standalone command after a
database or its properties change.

## What it does

1. Loads `NOTCMS_SECRET_KEY` and `NOTCMS_WORKSPACE_ID`
2. Fetches the current workspace schema from NotCMS
3. Generates the configured schema module and its `nc` client
4. Prints a query for the first database

## Options

| Option | Description | Default |
| --- | --- | --- |
| `-e, --env <PATH>` | Comma-separated environment file paths | `.env,.env.local,.dev.vars` |
| `--check` | Check whether the schema is current without writing | `false` |

`--check` exits with code 1 when the generated file is missing or out of date,
which makes it suitable for CI/CD.

## Examples

### Update the schema

```bash
npx notcms pull
```

### Load credentials from a custom env file

```bash
npx notcms --env .env.development pull
```

### Check without writing

```bash
npx notcms pull --check
```

## Generated schema

The command generates both the typed schema and a ready-to-use client:

```typescript
import { Client } from "notcms";
import type { Schema } from "notcms";

export const schema = {
  blog: {
    id: "abc123...",
    properties: {
      title: "title",
      content: "rich_text",
      published: "checkbox",
      publishDate: "date",
      author: "relation",
      tags: "multi_select",
    },
  },
} satisfies Schema;

export const nc = new Client({ schema });
```

You can add a package script for later updates:

```json
{
  "scripts": {
    "schema:pull": "notcms pull"
  }
}
```

## Change summary

After a successful write, `pull` summarizes added/removed databases and properties,
property type changes, and database IDs (with before/after values). `--check`
prints the same summary when the file is stale while preserving the file.

```text
Changed database ID: "blog"
  "old_id" -> "nids_new_id"
Added database: "releases"
```

A repeated pull prints `No semantic schema changes.` if only formatting or key
order changed. A missing previous file is identified as the first pull. Local
modules are never executed: generated object literals, bare keys, trailing
commas, and comments are supported. For expressions, single-quoted strings, or
other unsupported edits, the CLI explicitly says the summary is unavailable;
normal generation still continues, so review the file diff. Database renames
appear as removal/addition. An ID change does not by itself imply an outage.
