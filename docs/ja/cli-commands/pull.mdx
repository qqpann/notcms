## 概要

`pull`コマンドは、NotCMSワークスペースへ登録されたデータベースから、設定済みの
TypeScriptスキーマを生成または更新します。

```bash
npx notcms pull
```

最初のpullは`init`が自動で実行します。データベースまたはプロパティを変更した後に、
この単独コマンドを実行してください。

## 実行内容

1. `NOTCMS_SECRET_KEY`と`NOTCMS_WORKSPACE_ID`を読み込み
2. NotCMSから現在のワークスペーススキーマを取得
3. 設定されたスキーマmoduleと`nc`クライアントを生成
4. 最初のデータベース用クエリを表示

## オプション

| オプション | 説明 | デフォルト |
| --- | --- | --- |
| `-e, --env <PATH>` | カンマ区切りの環境ファイルパス | `.env,.env.local,.dev.vars` |
| `--check` | ファイルを書き込まずスキーマが最新か確認 | `false` |

`--check`は生成ファイルが存在しない、または古い場合に終了コード1を返すため、
CI/CDで利用できます。

## 例

### スキーマを更新

```bash
npx notcms pull
```

### 独自の環境ファイルから認証情報を読み込む

```bash
npx notcms --env .env.development pull
```

### ファイルを書き込まず確認

```bash
npx notcms pull --check
```

## 生成されるスキーマ

型付きスキーマと、すぐ利用できるクライアントの両方を生成します：

```typescript
import { Client } from "notcms";
import type { Schema } from "notcms";

export const schema = {
  blog: {
    id: "abc123...",
    properties: {
      title: "title",
      content: "rich_text",
      published: "checkbox",
      publishDate: "date",
      author: "relation",
      tags: "multi_select",
    },
  },
} satisfies Schema;

export const nc = new Client({ schema });
```

後から更新するためのpackage scriptも追加できます：

```json
{
  "scripts": {
    "schema:pull": "notcms pull"
  }
}
```

## 変更要約

保存成功後に DB・プロパティの追加／削除、型変更、DB ID の変更前後を表示します。
`--check` でもファイルが古い場合に同じ要約を表示し、ファイルは変更しません。

```text
Changed database ID: "blog"
  "old_id" -> "nids_new_id"
Added database: "releases"
```

整形やキー順序だけの変更では `No semantic schema changes.` と表示し、
以前のファイルがなければ初回 pull と表示します。ローカル module は実行しません。
生成するオブジェクトリテラル、引用符なしのキー、末尾カンマ、コメントに対応します。
式、シングルクォートの文字列など未対応の編集では要約できない旨を表示し、
通常の生成は継続します。ファイル差分を確認してください。DB 名変更は削除・追加として
表示し、ID 変更そのものが取得障害を意味するとは限りません。
