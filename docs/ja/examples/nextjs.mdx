NotCMSはNext.jsのサーバー側で使い、シークレットキーをブラウザへ渡さないようにします。
Next.js App Routerのプロジェクト内で[クイックスタート](/ja/quickstart)を進めてください。
以下はNotCMS 0.5.0以降と、`published` チェックボックスを持つ `blog` データベースの例です。
名前は生成されたスキーマに合わせて置き換えてください。

## 生成されたクライアントを使う

`notcms init` はスキーマを作り、`nc` をexportします。Next.jsはサーバー側で `.env.local` を読み込むので、
サーバーコンポーネントやサーバー専用の関数からそのクライアントをimportします。
`"use client"` を指定したコンポーネントにはimportしないでください。
自分でクライアントを作る場合は `new Client({ schema })` のように `schema` を渡します。
認証情報だけでは型付きのクエリを定義できません。

## 公開するページの一覧を取得する

非同期のサーバーコンポーネントから、次のような関数を呼びます。
相対importは、生成したスキーマの保存先に合わせて変更してください。

{/* docs-check */}
```typescript
import { nc } from "./notcms/schema";

export async function getPublishedPosts() {
  const [posts, error] = await nc.query.blog.list({
    where: { published: true },
  });
  if (error) throw error;
  return posts;
}

export type BlogSummary = (typeof nc.query.blog.$inferPages)[number];
```

`post.title` を表示し、`/blog/${post.id}` へリンクします。Notionで定義したプロパティは
`post.properties` に、ページのタイトルとIDはトップレベルにあります。
取得エラーをthrowすると、Next.jsのエラー境界でサービス障害を扱えます。
障害を、取得に成功した空の一覧として表示しないようにします。

## 個別ページを取得する

プロパティで検索すると、公開条件を適用しながら本文を取得できます。

{/* docs-check */}
```typescript
import { nc } from "./notcms/schema";

export async function getPublishedPost(id: string) {
  const [post, error] = await nc.query.blog.getFirst({
    where: { id: { in: [id] }, published: true },
  });
  if (error) throw error;
  return post;
}

export type BlogPage = typeof nc.query.blog.$inferPage;
```

`app/blog/[id]/page.tsx` で `params` をawaitしてIDを取り出し、この関数を呼びます。
結果が `null` の場合にだけNext.jsの `notFound()` を呼んでください。サービスの障害はエラーとして扱います。
`getFirst` は同期済みの本文を読むため、Notionの変更は次の同期後に反映されます。
`get(id)` との違いは[1ページの取得](/ja/usage/get)を参照してください。

Markdown本文は `post.content` にあります。`post.properties.content` ではありません。
コンテンツの信頼度に合ったMarkdownレンダラーで描画してください。
HTMLを許可する場合、信頼できないHTMLはページへ挿入する前にサニタイズします。

## 信頼できない本文を安全に描画する

SDKが返すMarkdownはデータであり、安全性が保証されたHTMLではありません。[同梱ブログテンプレート](https://github.com/qqpann/notcms/tree/main/examples/nextjs-simple-blog-template)の `MainContent` はMarkedでMarkdownを変換し、最後に `sanitize-html` でサニタイズしてからReactへ渡します。このテンプレートにはNode.js 22.12以降を使用してください。SDKの実行環境の要件は変わりません。

見出し、強調、リスト、表、コード、画像、`details`・`kbd` などの静的HTMLに対応します。Markdown記号はMarkdown構文として解釈されます。記号をそのまま表示するにはエスケープするか、インラインコード・コードブロックを使います。コード内の `<`・`>`・`&` は文字として保持します。見出しのアンカーには `notcms-heading-` を付けます。

リンクにはHTTP・HTTPS・mailto・相対パス・フラグメント、画像にはHTTP・HTTPS・相対パスを許可します。プロトコル相対URL、JavaScript・data・file URLは除去します。イベントハンドラー、インラインスタイル、任意のCSS class、SVG、MathML、script、form、埋め込みアプリケーションは非対応です。タスクリストのチェックボックスは操作できません。任意のiframeやHTMLアプリは再現せず、通常のリンクとして掲載してください。

これらはレンダラーの規則であり、SDKだけを導入しても適用されません。すべてのMarkdown・HTML変換を終えてからサニタイズし、依存するsanitizerを更新してください。HTMLのサニタイズは、外部画像やリンク先文書の実体・MIME・リダイレクト・アクセス制御を検証しません。その境界はメディアサービスとアプリケーションが担当します。

## 公開条件と更新方法を決める

予約公開、言語のフォールバック、一覧と個別ページそれぞれの確認には、
[検証済みのコンテンツレシピ](/ja/examples/content-recipes)を利用できます。
このガイドには、非同期の `params` を使ったNext.jsルートの例があります。
再利用できるクエリと公開判定のコードは
[`examples/content-recipes`](https://github.com/qqpann/notcms/tree/main/examples/content-recipes)
で管理し、SDKのテストで検証しています。

Notionの同期後は、アプリで設定したキャッシュも更新してください。
静的にビルドしたサイトでは、編集の反映や公開を取り消したページの削除に再ビルドが必要です。
アプリに合う方式を明示的に選んでください。SDKへのリクエスト自体は、Next.jsのキャッシュ無効化やデプロイを行いません。
