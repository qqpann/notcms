title: Astroとの連携

NotCMSはコンテンツを提供し、AstroはそれをいつHTMLにするかを決めます。
Astroのサーバー側コードで取得し、ページのデータをテンプレートに渡します。

このガイドでは、生成済みの `nc` クライアントと、同期済みの `blog` データベースを使います。
例のプロパティは `published`（チェックボックス）、`slug`（テキスト）、`cover`（ファイル＆メディア）です。
データベース名やプロパティ名は自分のスキーマに合わせてください。

新規プロジェクトから試す場合は、[実行可能なAstroサンプル](https://github.com/qqpann/notcms/tree/main/examples/astro)を使えます。
スキーマ生成、環境変数の設定、一覧・詳細ページをまとめています。

## いつ取得するかを選ぶ

| 方式 | 向いている用途 | コンテンツの更新 |
| --- | --- | --- |
| 静的生成 | ビルドのタイミングで公開できるブログやドキュメント | 同期後に再ビルド・デプロイする |
| オンデマンドレンダリング | リクエストごとに新しい内容を表示したいページ | リクエスト時に同期済みの最新内容を取得する |

使うSDKのクエリは同じです。静的生成ではビルド時に認証情報が必要です。
オンデマンドでは配備先のサーバーでも認証情報を使えるようにし、
その環境に合った[Astroアダプター](https://docs.astro.build/ja/guides/on-demand-rendering/)を選びます。

認証情報はサーバー側だけで扱います。実行サンプルではCLIの `.env.local` をNodeのビルドで読み込みます。
ほかの実行環境は[Astroの環境変数ガイド](https://docs.astro.build/ja/guides/environment-variables/)を参照してください。

## 何を公開するかを決める

`published` のようなプロパティで、サイトの公開条件を表します。

```ts
const [posts, error] = await nc.query.blog.list({
  where: { published: true },
});
if (error) throw error;
```

一覧と詳細には同じ公開条件を適用します。フィルターはサイトに表示する内容を選ぶもので、
ワークスペースのキーが読める範囲を制限するものではありません。
そのワークスペースの利用者へ提供するコンテンツだけを同期してください。メディアのURLは公開URLです。

## コンテンツをルートにする

静的サイトでは、公開記事の一覧から作成するページを決めます。
Astroの `getStaticPaths` で、記事ごとにルートを返します。

```ts
export async function getStaticPaths() {
  const [posts, error] = await nc.query.blog.list({ where: { published: true } });
  if (error) throw error;
  return posts.map((post) => ({ params: { id: post.id } }));
}
```

`src/pages/blog/[id].astro` では、そのIDから本文を含むページを取得します。

```ts
const [post, error] = await nc.query.blog.get(Astro.params.id!);
if (error) throw error;
```

一覧取得後に内容が変わることもあるため、詳細を表示する前にも公開状態を確認します。
静的生成中にAPI取得が失敗した場合は、不完全なサイトを公開せずビルドを止めます。
記事を非公開にしたときも、新しいビルドのデプロイが必要です。

オンデマンドのslugルートでは、`findFirst({ where: { slug, published: true } })` を使います。
該当なしは404、API取得の失敗はサービスエラーとして扱います。slugの一意性と変更時のリダイレクトはサイト側で管理します。
使い方と利用できるリリースは[1件のページ取得](/ja/usage/get)を参照してください。

## 本文と画像を表示する

`post.content` にはMarkdownが入ります。サイトに合ったMarkdownレンダラーを選び、
生成したHTMLをサニタイズして表示します。実行サンプルでは、レンダラーを決める前でも取得を試せるよう、
エスケープしたテキストを表示しています。

ファイル＆メディアのプロパティには画像URLが入ります。たとえば先頭のカバー画像は次のように表示できます。

```astro
{post.properties.cover?.[0] && (
  <img src={post.properties.cover[0]} alt={post.title} />
)}
```

最適化が必要なら、このURLをAstroの画像機能で扱います。
画像処理はサイト側で選択でき、SDKが特定のレンダラーやレイアウトを要求することはありません。

## スキーマの変更を取り込む

Notionのプロパティを変えたら、同期完了後に `npx notcms pull` を実行し、生成された型を確認します。
[CIでのスキーマ確認](/ja/cli-commands/schema-ci)を使うと、次のデプロイまでにずれを見つけられます。
