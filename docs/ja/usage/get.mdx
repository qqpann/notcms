---
title: 1件のページを取得する
description: ページIDによる取得と、プロパティによる検索を使い分ける
---

ページIDが分かっているなら `get`、slugなどのプロパティで探すなら `getFirst` を使います。
どちらもページのプロパティとMarkdownの本文 `content` を返します。
以下のデータベース名・プロパティ名は、生成したスキーマに合わせてください。

## IDで取得する

IDは特定のページを指します。タイトルやslugが変わっても同じページを参照したい場合に使います。

```ts
const [post, error] = await nc.query.blog.get("page-id-123");
if (error) throw error;
console.log(post.content);
```

ページが存在しなければ `get` はエラーを返します。空のページとしては扱いません。

## プロパティで探す

プロパティによる検索は、サイトの条件に合うページを探します。たとえば、公開済みの記事をslugで取得します。

{/* docs-check */}
```ts
import { nc } from "./notcms/schema";

const [post, error] = await nc.query.blog.getFirst({
  where: { slug: "hello-world", published: true },
});
if (error) throw error;
console.log(post?.content);
```

一致するページがなければ `post` は `null` です。アプリではその結果を使って404を表示できます。
リクエスト自体の失敗は、ページなしではなくエラーとして扱います。

<Note>
`getFirst` は NotCMS 0.5.0 以降で利用できます。利用前に `notcms` パッケージを更新してください。
</Note>

## どの1件を選ぶか

`where` と `sort` は [list()](/ja/usage/list) と同じです。複数のページが一致した場合は、
その並び順の先頭を返します。一意性を保証する機能ではありません。

```ts
const [post, error] = await nc.query.blog.getFirst({
  where: { published: true },
  sort: { publishedAt: "desc" },
});
```

「最初の1件」に意味がある場合は、並び順を指定します。slugのルートでは、編集時に重複を避け、
変更時のリダイレクトをサイト側で管理します。言語別slugやIDによる代替は
[URLレシピ](/ja/examples/content-recipes)を参照してください。

## 結果を扱う

| 結果 | `post` | `error` |
| --- | --- | --- |
| ページを取得できた | `properties` と `content` を含むページ | `null` |
| `getFirst` で一致するページがない | `null` | `null` |
| リクエストが失敗した | `undefined` | `Error` |

型は生成スキーマから推論されます。ページを使う前に `error` を確認し、`getFirst` では `null` も扱います。
再試行の判断は[エラーとレート制限](/ja/usage/errors-and-rate-limits)を参照してください。

<Accordion title="リクエストと並び順の詳細">
- `getFirst` は `limit=1&include=content` を付けた一覧取得を1回だけ送ります。転送するのは先頭の1件とその本文だけです。
- `getFirst` は `list` と同じく、NotCMSへ同期済みの内容を返します。`get` と違いNotionへは問い合わせないため、最後の同期より後の変更（アクセスできなくなったページなど）は次の同期後に反映されます。
- 並び順の省略時や同値の場合は、登録順、次にページIDで並びます。
- タプルの3番目は成功時と該当なし時に一覧レスポンス、失敗時に失敗したレスポンスです。ネットワーク障害では `undefined` になります。SDKは自動再試行しません。
</Accordion>
