## 基本的なセットアップ

NotCMSを使用するには、スキーマと認証情報を使用してクライアントを初期化する必要があります：

{/* docs-check */}
```typescript
import { Client } from 'notcms';
import { schema } from './notcms/schema';

const nc = new Client({
  schema,
  secretKey: process.env.NOTCMS_SECRET_KEY,
  workspaceId: process.env.NOTCMS_WORKSPACE_ID
});
```

## 前提条件

クライアントを初期化する前に、以下を確認してください：

1. **スキーマの生成** - `npx notcms init` で最初のスキーマを生成し、`npx notcms pull` で更新
2. **環境変数** - API認証情報の設定
3. **NotCMSのインストール** - プロジェクトの依存関係に `notcms` を追加

## 環境変数

### 必須変数

```env
NOTCMS_SECRET_KEY=your-secret-key
NOTCMS_WORKSPACE_ID=your-workspace-id
```

### 環境変数の読み込み

<Tabs>
  <Tab title="Next.js">
    ```typescript
    // Next.jsは.env.localを自動的に読み込みます
    import { Client } from 'notcms';
    ```
  </Tab>
  
  <Tab title="Node.js">
    Node.jsだけでファイルを読み込めます。

    ```bash
    node --env-file=.env.local app.ts
    ```

    `dotenv` を使う場合は、`dotenv.config()` のあとで生成クライアントを動的な `import()` で読み込みます。
    静的な `import` は環境変数を設定する前に実行されます。

    ```typescript
    import dotenv from 'dotenv';
    dotenv.config({ path: ".env.local" });
    
    const { nc } = await import('./notcms/schema');
    ```
  </Tab>
  
  <Tab title="Vite">
    NotCMSクライアントはサーバーのエンドポイントまたはサーバーサイドレンダリングで使用します。
    `VITE_` で始まる変数はブラウザへ公開されるため、`NOTCMS_SECRET_KEY` を `VITE_` 変数へ入れないでください。
    サーバーランタイムでsecretを読み込み、そこで `Client` に渡します。

    生成された `notcms/schema` モジュールも、読み込まれた時点で `process.env` からクライアントを作ります。
    しかし Vite は `.env` ファイルの値を `process.env` へ入れません。
    [Astroのサンプル](https://github.com/qqpann/notcms/tree/main/examples/astro)と同じように、Vite の設定ファイル（Astro では `astro.config.mjs`）で `NOTCMS_` の値を `process.env` へ入れてください。

    ```typescript
    // vite.config.ts
    import { defineConfig, loadEnv } from 'vite';

    export default defineConfig(({ mode }) => {
      // デプロイ先の環境で設定した値を優先します。
      const local = loadEnv(mode, process.cwd(), 'NOTCMS_');
      for (const [key, value] of Object.entries(local)) {
        process.env[key] ??= value;
      }
      return {
        // 既存の設定
      };
    });
    ```
  </Tab>

  <Tab title="Cloudflare Workers">
    Workers は、互換性フラグ `nodejs_compat` が有効で互換性日付が 2025-04-01 以降のとき、Worker の変数とシークレットを `process.env` に入れます。
    互換性日付が 2026-08-04 以降なら、このフラグは最初から有効です。

    ```jsonc
    // wrangler.jsonc
    {
      "compatibility_date": "2026-11-01",
      "compatibility_flags": ["nodejs_compat"]
    }
    ```

    この設定がないと `process.env` は空になり、値を自分で `Client` に渡していても、生成された `notcms/schema` モジュールを読み込んだ時点で `secretKey is required` で失敗します。
    キーは `npx wrangler secret put NOTCMS_SECRET_KEY` で保存し、`NOTCMS_WORKSPACE_ID` は `vars` かシークレットに設定します。
  </Tab>
</Tabs>

## フレームワーク別のセットアップ

### Next.js App Router

```typescript
// app/lib/notcms.ts
import { Client } from 'notcms';
import { schema } from '@/notcms/schema';

// サーバー専用クライアント
export const nc = new Client({
  schema,
  secretKey: process.env.NOTCMS_SECRET_KEY!,
  workspaceId: process.env.NOTCMS_WORKSPACE_ID!
});
```

### Remix

```typescript
// app/lib/notcms.server.ts
import { Client } from 'notcms';
import { schema } from '~/notcms/schema';

// .server.ts拡張子でサーバー専用を明示
export const nc = new Client({
  schema,
  secretKey: process.env.NOTCMS_SECRET_KEY!,
  workspaceId: process.env.NOTCMS_WORKSPACE_ID!
});
```

### SvelteKit

```typescript
// src/lib/notcms.ts
import { Client } from 'notcms';
import { schema } from '../notcms/schema';
import { 
  NOTCMS_SECRET_KEY, 
  NOTCMS_WORKSPACE_ID 
} from '$env/static/private';

export const nc = new Client({
  schema,
  secretKey: NOTCMS_SECRET_KEY,
  workspaceId: NOTCMS_WORKSPACE_ID
});
```

生成されたスキーマのモジュールは読み込まれた時点で `process.env` を読むため、上の Vite のタブのとおり値を `process.env` へ入れてください。

## トラブルシューティング

### よくある問題

<AccordionGroup>
  <Accordion title="環境変数が読み込まれない">
    - プロジェクトルートに `.env.local` ファイルが存在することを確認
    - 実行環境が `.env.local` を読み込んでいることを確認（`node --env-file=.env.local`、または `dotenv` のあとで生成クライアントを動的な `import()` で読み込むなど）
    - 生成された `notcms/schema` モジュールは、読み込まれた時点で環境変数を読みます。自分の `Client` に `secretKey` と `workspaceId` を渡しても、この読み込みは省けないため、先に環境変数へ設定してください（上の Vite と Cloudflare Workers のタブを参照）
    - 変数名が正確に一致していることを確認
  </Accordion>
  
  <Accordion title="認証に失敗">
    - `NOTCMS_SECRET_KEY` が正しいことを確認
    - `NOTCMS_WORKSPACE_ID` がワークスペースと一致することを確認
    - APIキーに必要な権限があることを確認
  </Accordion>
  
  <Accordion title="スキーマが見つからない">
    - `npx notcms pull` を実行してスキーマを生成
    - インポートパスが正しいことを確認
    - スキーマファイルが正しくエクスポートされていることを確認
  </Accordion>
  
  <Accordion title="TypeScriptエラー">
    - NotCMSを最新バージョンに更新
    - `npx notcms pull` でスキーマを再生成
    - TypeScriptバージョンの互換性を確認
  </Accordion>
</AccordionGroup>
